# 广州氢能｜项目出图工作流指引

适用于本项目的建筑白模、宋式庭院、室内与屋顶花园效果图。从原始机位出发，依次完成标注、渲染、独立评审、定版和分区精修。本仓库用 6 号 V33 的白模、标注、评审证据和 4K 成图演示全流程。文中其他视角是项目复盘案例。更新于 2026-11-27。

Codex 可使用仓库内的 [architectural-render-workflow skill](.agents/skills/architectural-render-workflow/SKILL.md)。在任务中指定 `$architectural-render-workflow` 可调用标注、渲染、评审或精修流程。

## 1. 项目入口与交接

| 环节 | 项目中的对话 | 交给下一环节的材料 |
| --- | --- | --- |
| 标注 | 标注 | 当前白模、材质标注、配景与光感标注、重点节点、参考图分工和渲染提示词草稿 |
| 渲染 | 渲染（6 号）、渲染2号（12 号）、渲染3号（8 号）、渲染4号（13 号）、渲染5号（14 号） | 编号的原生全景、实际提示词、输入来源、原像素局部、白模对照和自检结论 |
| 评审 | 评审 | 对实际成图逐项复核，写明证据、偏差、修改指令和回归检查项，回发对应视角 |
| 精修 | 精修 | 仅接收已经明确授权的具体母图版本，交付 4K 全景、预览、原像素局部、接缝核验及来源记录 |

项目原模型与 6 号白模在 [氢能渲染/rendering](氢能渲染/rendering/)。标注与渲染在 [氢能渲染](氢能渲染/)，精修工件在 [outputs](outputs/)。已有的 [白模到渲染工作流程与注意事项](氢能渲染/白模到渲染_工作流程与注意事项.md) 详细记录了 6、12 号的投影、家具和节点纠偏，其中也保留了原项目的本地路径。

## 2. 标注｜把设计意图落到白模

1. **锁定机位。** 在 Rhino 模型中确定相机、取景和画幅，导出无标记白模。归档实际底图的路径、像素尺寸和 SHA-256。同名截图可能被覆盖，每轮先看画面及哈希。换机位后重新制作标注与投影辅助图。
2. **拆开材质与配景。** 材质图标结构、屋瓦、木、石、玻璃、纱帘及水体。配景图标家具件数、方向与落地范围，乔灌草层次、岩瀑、汀步、石岸和通行。用与总图对应的编号补节点大样，覆盖檐下、窗口、平台、水线等容易误读的位置。
3. **给每份参考指定用途。** 说明参考图用于哪种材质、树形、家具结构或光线。单独注明手绘线和辅助体块的性质。6 号平台红边是指定轮廓，12 号新版白模的红盒只供透视判断。只在用户确认时把示意位置或数量升级为硬约束。
4. **交出本轮任务单。** 列出本轮改动、跨轮保留项、撤回项、参考素材和每处可见验收点。明确哪些建筑细部可改，哪些檐线、柱网、水口、标高和通道仍由白模控制。标记应放在标注副本中，保留干净白模。

实例见 [6 号材质标注](氢能渲染/6号视角_渲染标注/6号视角_材质标注.png) 和 [6 号配景总图](氢能渲染/6号视角_渲染标注/6号视角_宋式园林_配景总图.png)。V33 后续新增内退幕墙，用独立控制图明确位置及保留的白模轮廓。

## 3. 渲染｜从当前白模出候选

1. **接单先读指引和实际输入。** 核对白模、有效标注、目标参考和用户最新一轮原话。输入中明确白模负责机位和建筑，标注负责改动范围，意向图负责指定外观。历史选稿用干净局部传递已经确认的布置，初版及设计回改从当前白模独立生成。
2. **把要求写成能验收的画面关系。** 提示词按「机位与几何 → 本轮改动 → 保留项 → 材质、景观与光 → 重点自检」组织。比如，玻璃内退要能读出檐前缘、檐底与玻璃顶收口。会议室家具的可见范围由机位、楼板、玻璃和纱帘共同决定。
3. **用平行构件校投影。** 从已知同向的白模直边取点，桌沿、灯槽、柜顶和平台直段核查共同相机。弧段单独核对轮廓。家具在相近景深找建筑尺度，优先使用该场景的已知尺寸。效果图上的净宽、净高判断有疑问时回到模型量取。
4. **按问题决定重出范围。** 建筑边界或整体设计有偏差时，回到白模重出并调整控制输入。针对已选底图的定域修正或光感分支，可按任务明确范围使用同坐标合成，记录使用了哪些生成区域和哪些原图像素。独立保存原生成、候选和交付版，避免覆盖选稿。
5. **自检后送评审。** 看全景比例，再看本轮和高风险节点的原像素局部。与白模做同尺寸、同画幅对照，只做等比归一。存下实际用过的提示词、输入顺序和各图用途、候选取舍、原生输出尺寸与哈希。例中 8000 × 4286 是白模输入，常见原生渲染为 1713 × 918 或 1714 × 918。

## 4. 评审｜按证据退回或定版

评审读取实际交付图、当前白模、任务单和需要保留的上版。标注或提示词能帮助定位问题，结论以成图和对照为依据。

| 顺序 | 核对什么 | 证据 |
| --- | --- | --- |
| 1. 建筑与空间 | 相机、层数、檐边、柱脚、楼板、玻璃上下边及内退、平台和水陆高差 | 白模与成图同尺寸并排，必要时加轮廓叠图、剖视或同向直边取点 |
| 2. 布置与遮挡 | 家具件数、朝向、体量、落地、通行，玻璃与栏板分层，室内与露台的前后关系 | 同位置原像素局部，有需要时同已选稿或用户圈线并排 |
| 3. 景观与光色 | 岸石落脚入水、瀑顶与瀑脚连续、主树根干冠连贯、步道可走，材质及明暗层次 | 全景与对应节点，光感分支可做同位置明度抽样 |
| 4. 变更回归 | 本轮各项有没有兑现，原有结构、家具和通道有没有在改图中走样 | 本轮任务清单与上一版已选设计逐项对照 |

**退回格式。** 每条写「位置和对象 → 当前偏差 → 目标状态 → 保护项 → 验收对照」。例如 8 号近端会议室被木平台挡住桌面，只应在左侧轻纱后露小段椅背。远端按白模视线保留一截斜桌面及少量椅背。两处分别给固定坐标对照，避免用增加家具数量表现进深。

**评审结论。** 对检查项标明通过、待回改或需模型实测。写清局部测点的条件和已知残差。相机、结构、功能关系或关键交付项仍有明显偏差时回到渲染，连续回改仍漂移时更新白模控制图或回模型校正。图像像素对照适用于投影核查，施工尺寸与净宽由模型复核。

**版本状态。** 区分「试稿」「渲染已交付」「评审已复核」「用户选定」「指定版本已授权精修」「4K 已交付」。记录结论适用的文件或范围。比如 8 号 V7 已获授权并完成精修，V8 是另存的斜阳光感试稿。文件编号递增也要保留用户实际选中的母图。

## 5. 精修｜重建细节并按原比例拼合

1. **锁母图和核验目标。** 明确已授权的视角、版本、文件、原生尺寸及哈希，锁定副本。交接列出必须保留的关键节点、本轮允许修改的局部及残余偏差。以长边 3840 为例，等比计算并取整，1713 × 918 对应 3840 × 2058，1714 × 918 对应 3840 × 2057。记录实际尺寸。
2. **按构件安排重叠分区。** 保存各裁区在母图和目标画布的位置。窗框、连续檐线、木格栅、主树、家具组、水岸和瀑布尽量由一整区覆盖，交叠处留足共同特征。分区提示词明确景深、构造和光色。生成细节后保留原裁图、实际提示词、原生生成与候选取舍，并记录必要的局部放大倍率。
3. **配准、统一光色、选缝。** 已用流程包括 SIFT 特征匹配、单一相似变换、按母图校准低频曝光和色温、选缝与多频段融合。回查整图覆盖、局部配准和接缝位置。关键节点若跨区错齿或产生假构件，优先用整块重新生成并重新配准。边界极敏感处可保留少量母图像素，并在交付记录中注明。
4. **按 100% 原像素复核。** 查檐口、窗框、玻璃底槽、格栅、家具脚、石岸、树干、水丝和反光是否断接、重影或错位。按母图同坐标查构造和光色，关键区域保存局部对照、接缝位置图与抽查结果。后续限域补景使用蒙版另存，对范围外的一致性用实际像素差复核。
5. **导出并归档。** 输出 sRGB 4K PNG、JPG 和轻量预览，附 100% 局部、前后对照及核验说明。归档母图、分区坐标、实际提示词、原生生成、拼合脚本或参数、接缝证据和文件哈希。说明哪些纹理来自重建，记录可见偏差和用户验收状态。

| 实例 | 可复用的做法 |
| --- | --- |
| 6 号 V33，3840 × 2057 | 8 个重叠分区保住内退幕墙及平台双座，重点检查窗框、灯带和瀑脚接缝。[精修记录](outputs/6号_V33_内退玻璃幕墙_4K精修/交付说明.txt) |
| 8 号 V7，3840 × 2058 | 弧窗由整块分区重建，两道白檐取样核对。两间会议室用完整分区处理可见家具及纱帘遮挡。 |
| 12 号 V35，3840 × 2058 | 9 个基础分区，加整片连续木吊顶修复跨区错齿。逐层核对露台、栏板、纱帘与会议家具。 |
| 13 号 V19，3840 × 2058 | 11 个重叠分区，复核四处铺地接水口、两组浅草坡与茶席件数，并用同位置抽样比较光照。 |
| 14 号 V05，原生 1713 × 918 | 四席逐把对照款式，核对水口、曲檐、两道透明栏板及通行，记录左端主檐偏差。 |

## 6. 可复制的交接单

```text
视角 / 当前机位 / 本轮版本 / 日期
底图与授权：白模或锁定母图路径、尺寸、SHA-256、授权范围
输入分工：标注、节点、参考图、上版局部各负责什么
本轮要求：逐项写清对象、位置、范围和可见结果
保留与撤回：列出跨轮保留项，以及本轮已失效的旧要求
核验：原像素局部、同尺寸全景、关键边线或接缝检查
交付：实际文件、原生或精修尺寸、实际提示词、来源记录
状态：版本所处环节、未通过项、下一步交给哪个环节
```

同一视角用「项目_视角_机位或底图版本_Vxx_本轮主题」命名。精修目录名带上母图版本，局部补景或光感试稿单独留档。部分历史日志和脚本保留当时的绝对本机路径作为溯源，迁移运行时需改为实际检出目录。
